## Agents and machines

An **agent** is the name, instructions, and model you @mention. A **machine** is where that agent runs: in Rox, in Cursor, or on a computer of your own.

Create agents in **Settings → Agents**. Connect a machine in **Settings → Machines**.

## On the Rox desktop app

The desktop app bundles `roxd`, so there is nothing to download. Open **Settings → Machines** and use the **This computer** card. **Set up** looks for a coding agent already installed on your machine, then **Set up** that agent configures, pairs, and starts roxd and creates the agent. No terminal and no pairing code. Open **Options** to choose a different agent, set the **Workspace folder**, or turn on **Full access**. Keep the app open while agents run.

The manual `roxd` steps below are for machines without the desktop app (servers, a second computer), and both kinds of machine can be paired to the same account.

## Rox daemon

Use your local coding agent from Rox. `roxd` runs on your computer, connects your agent to Rox, and keeps its sessions available from your workspace.

<Info>
  Rox Daemon is for advanced users that want to connect agents running in your terminal. For example, if you run Claude Code on your server.
</Info>

Run the Rox daemon (`roxd`) on your computer or server.

## Before you start

You need a macOS, Linux, or Windows computer that can stay online and an installed, authenticated coding agent. `roxd` recognizes Claude Code, Codex, OpenCode, OMP, OpenClaw, and Hermes. You can also configure a custom command for an Agent Client Protocol (ACP) agent.

`roxd` connects out to Rox. You do not need a public webhook endpoint, port forwarding, or an HTTPS tunnel.

<Warning>
  Your local agent can run commands and edit files on your computer. Choose a dedicated workspace and review access before sharing a machine with your team. Leave permission bypass off unless you intend to allow actions without approval.
</Warning>

## Connect your machine

<Steps>
  <Step title="Install roxd">
    Run the install command for your computer in a terminal:

    <Tabs>
      <Tab title="macOS and Linux">
        ```bash
        curl -fsSL https://raw.githubusercontent.com/macro-inc/macro/main/crates/coding_agent_worker/install/install.sh | sh
        ```

        This installs `roxd` to `~/.local/bin` and adds that folder to your `PATH` in your shell's startup file (`~/.zshrc`, `~/.bashrc` and `~/.bash_profile`, or fish's `conf.d`), once. Open a new terminal afterwards. To leave your startup files alone, run `curl -fsSL … | sh -s -- --no-modify-path` or set `ROXD_NO_MODIFY_PATH=1`.
      </Tab>
      <Tab title="Windows">
        In PowerShell:

        ```powershell
        irm https://raw.githubusercontent.com/macro-inc/macro/main/crates/coding_agent_worker/install/install.ps1 | iex
        ```

        This installs `roxd.exe` to `%LOCALAPPDATA%\Programs\roxd` and adds that folder to your user `PATH`. Open a new terminal afterwards.
      </Tab>
    </Tabs>

    You can also download the archive for your operating system and architecture from [Rox releases](https://github.com/macro-inc/macro/releases) and extract it.

    Open **Settings → Machines → New machine** in Rox. The page walks you through installation, configuration, and pairing.
  </Step>

  <Step title="Run roxd">
    Open a terminal and run:

    ```bash
    roxd
    ```

    Keep the terminal open while you use your machine.

    On first launch, **Quickstart** lists the agents available on your machine. Select one, or choose **Custom command** to enter an ACP launch command.

    Set **Workspace** to the directory your agent should work in. Everything else about the machine is managed in Rox.

    Select **Create and pair** to generate your device code.

    <Note>
      Claude Code and Codex use ACP adapters, which `roxd` installs with `npm` the first time you select them. Their presets require the agent's command and `npm` to be available in the shell where you start `roxd`. On Windows, Claude Code works from either its native installer or `npm install -g @anthropic-ai/claude-code`.
    </Note>
  </Step>

  <Step title="Enter your pairing code">
    The **Pair roxd** panel shows a device code and a link to Rox. If you are already in the terminal overview, press <kbd>p</kbd> to open pairing. Press <kbd>c</kbd> to copy the code.

    Open the pairing link, or go to **Settings → Machines → New machine**. Enter your code and click **Look up**.

    <Frame caption="Example only—enter the code from your own roxd terminal.">
      ![The roxd terminal with a device code and approval link in the Pair roxd panel](/images/roxd-pairing-example.png)
    </Frame>

    Check that the code and computer match your terminal, review the machine's settings, then click **Approve**.

    `roxd` connects automatically after approval. It saves your agent, workspace, and credential in `~/.roxd/roxd.toml` (`%USERPROFILE%\.roxd\roxd.toml` on Windows). Keep this file private; do not commit it to a repository.
  </Step>
</Steps>

## Create an agent that uses your machine

**This computer** creates the agent for you. For a machine you paired from a terminal, open **Settings → Agents** and click **Add agent**.

In **New agent**, set the name, **@tag**, and instructions. Under **Where it runs**, choose **In your harness** and pick the machine under **Harness**. Under **Who can use it**, choose **Private** or **Team**, then save. @mention the agent to start a session on your machine. A **Private** agent can only be mentioned by you.

## Keep your machine connected

Leave `roxd` running and your computer awake while you use the machine. Its terminal shows your sessions, configuration, and logs. You can also check the machine in **Settings → Machines**.

To reconnect later, run `roxd` again; it loads `~/.roxd/roxd.toml` from any directory. If you remove the machine, pair it again before using it. Only one `roxd` can run with a given configuration at a time.

## Run more than one machine on a computer

Each machine has its own configuration. The first one uses `~/.roxd/roxd.toml`. Give every other machine a profile name:

```bash
roxd --profile work
```

A profile keeps its configuration in `~/.roxd/profiles/work.toml` and pairs as a new machine named after your computer and the profile, such as `my-laptop · work`. Rename it in **Settings → Machines**. Run `roxd --profile work` again to reconnect it.

If you start `roxd` while another `roxd` already runs the default configuration, it offers to create a profile and suggests a name. Press <kbd>Enter</kbd> to accept it or type another name, then set up the new machine in **Quickstart**.

To see every machine on your computer, run:

```bash
roxd profiles
```

It lists each profile with its configuration file, the machine it is paired to, and whether a `roxd` is running it now. Profile names use lowercase letters, digits, `-`, and `_`.

### Configurations in project folders

Older versions of `roxd` read `roxd.toml` from the folder you started them in. When you run `roxd` in a folder that still has one, `roxd` moves it into `~/.roxd` and keeps running that machine. It becomes `~/.roxd/roxd.toml` if you have no default configuration yet. Otherwise it becomes a profile named after the folder. `roxd` prints where the file went and the command to use from now on, such as `roxd --profile my-project`.

## Update roxd

`roxd` updates itself. While it runs, it checks for a new release every hour, downloads it, and verifies its checksum and that it starts. Your `roxd.toml` and pairing are kept. If an update fails, `roxd` keeps running the current version and shows the error in its **Logs** tab.

- **macOS and Linux:** `roxd` replaces itself in place as soon as no agent turn is running. Your agent keeps running through the update, so its sessions and anything it started stay alive.
- **Windows:** the new version is installed next to the running one, and the footer shows **Update … ready — restart roxd to use it**. Quit `roxd` and start it again to use it. The `roxd` command always starts the newest installed version and removes older ones.

To see what the updater did, read `~/.roxd/logs/update.log` (`%USERPROFILE%\.roxd\logs\update.log` on Windows). Each line is one JSON event: a `check` with the version found, a `download` with its size and whether the checksum matched, an `apply` with the versions and how the new one was started, and a `startup` line each time `roxd` starts, including after an update. The log never holds tokens or prompts. At about 1 MB it moves to `update.log.1`.

To update right away, run the install command again and restart `roxd`.

To install a specific release, set the `ROXD_VERSION` environment variable to its tag, such as `v2026.10.18.0`, before running the install command. A running `roxd` still updates itself to the latest release.

To turn automatic updates off, add this to `roxd.toml`:

```toml
[update]
auto = false
```

or start `roxd` with `ROXD_NO_UPDATE=1` set. `roxd` then only changes when you run the install command again.

## Troubleshooting

- **Your agent is missing from Quickstart:** check that it is installed and its command is available in the terminal where you launch `roxd`. For a different ACP agent, use **Custom command**.
- **Your code is invalid or expired:** start a new pairing from the terminal and enter the new code. The code in the screenshot is only an example.
- **Your machine is offline:** check that your computer is awake, `roxd` is running, and it can reach Rox. Check the terminal's **Logs** tab for errors.
- **`roxd` says your config sets `[identity]` or a `scope` in `[credentials]`:** delete those lines from `~/.roxd/roxd.toml`. The machine's name, access, and permission bypass are set in **Settings → Machines**.
- **`roxd` asks you to pair again after an update:** run `roxd` from the project folder you used to start it in. It moves that folder's `roxd.toml` into `~/.roxd` and tells you the command to use from now on. Run `roxd profiles` to see every machine on your computer.
- **You had `allow_permission_bypass = false` in `roxd.toml`:** that setting is gone, and your computer no longer has a local veto. Whether a machine may bypass permission requests is set by the machine's managers in **Settings → Machines**, under **Allow bypassing permission requests**.
